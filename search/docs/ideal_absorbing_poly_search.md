# Ideal Absorbing Polynomial Relation Search

## 1. Problem Definition

All computations are over the finite field $\mathbb{F}_p$.

The input integral set is

$$
G=\{I_1,\ldots,I_N\}.
$$

Each $I_i$ is a full integral tag, for example

```text
FI{nu}
BFI[XU]{nu}
BFI[XD]{nu}
BFI[YU]{nu}
BFI[YD]{nu}
BBFI[XU,YU]{nu}
BBFI[XU,YD]{nu}
BBFI[XD,YU]{nu}
BBFI[XD,YD]{nu}
```

Different heads or boundary tags define different objects, even if the same $\nu$ appears.

For each boundary condition or projection $b$, the input gives a truncated formal series

$$
I_i^{(b)}(\delta)
=
\sum_{r=0}^{D} a_{i,b,r}\,\delta^r .
$$

The target is to find polynomial-coefficient relations

$$
\sum_{i=1}^{N} P_i(\delta)\,I_i(\delta)=0,
$$

where

$$
P_i(\delta)=\sum_{k=0}^{M} c_{i,k}\,\delta^k,
\qquad c_{i,k}\in\mathbb{F}_p .
$$

Define one coefficient unknown for each pair $(i,k)$:

$$
u_{i,k}=c_{i,k}.
$$

Separately, define the monomial-integral object

$$
E_{i,k}=\delta^k I_i .
$$

The linear system unknown is $u_{i,k}$. A relation is not an equation like $\sum u_{i,k}=0$; a relation is the formal identity

$$
\sum_{i,k} c_{i,k}\,E_{i,k}=0,
$$

where the coefficients $c_{i,k}$ are given by one null vector of the linear system.

For each $b$ and coefficient order $n$, the relation imposes

$$
\sum_{i=1}^{N}\sum_{k=0}^{\min(M,n)}
c_{i,k}\,a_{i,b,n-k}=0 .
$$

Equivalently, define the formal-series matrix $A$ whose rows are indexed by $(b,n)$ and whose columns are indexed by $(i,k)$:

$$
A_{(b,n),(i,k)}
=
\begin{cases}
a_{i,b,n-k}, & n\ge k,\\
0, & n<k .
\end{cases}
$$

The polynomial relation search is the homogeneous system

$$
A u=0 .
$$

The mathematical goal is a formal-series identity. Since only finitely many series coefficients are available, the algorithm may use a training degree window to generate candidate relations and must check each accepted relation on held-out coefficients.

This document describes the ideal absorbing search algorithm. It is not constrained by the current dense RREF implementation.

## 2. Ordering and Leading Variables

The algorithm needs a total order on monomial-integral objects $E_{i,k}$, equivalently on coefficient unknowns $u_{i,k}$.

The intended order is:

1. Compare integral tags $I_i$ by the existing integral complexity order.
2. If the integral tag is the same, compare larger $k$ as more complex.

Thus

$$
E_{i,k_1} > E_{i,k_2}
\quad\text{if}\quad
k_1>k_2
$$

for the same integral $I_i$.

The algorithm processes columns from simpler to more complex. Therefore, when the column for $u_{i,k}$ is found to be dependent on previous columns, the previous columns correspond to simpler objects $E_{j,\ell}$ and the resulting formal relation has $E_{i,k}$ as its leading object.

A relation is stored in normalized leading form:

$$
E_{i,k}
+
\sum_{(j,\ell)<(i,k)}
r_{j,\ell}\,E_{j,\ell}
=0 .
$$

The leading object is $E_{i,k}$.

The purpose of the search is not to output an arbitrary nullspace basis. The purpose is to find useful leading relations that express more complex monomial-integral objects through simpler ones.

## 3. Absorb Principle

Suppose an accepted relation has leading object $E_{i,k_0}$:

$$
E_{i,k_0}
+
\sum_{(j,\ell)<(i,k_0)}
r_{j,\ell}\,E_{j,\ell}
=0 .
$$

Multiplying the whole relation by $\delta^s$ gives

$$
E_{i,k_0+s}
+
\sum_{(j,\ell)<(i,k_0)}
r_{j,\ell}\,E_{j,\ell+s}
=0 .
$$

Therefore the coefficient unknown $u_{i,k_0+s}$ does not need to be searched again, provided every shifted term remains inside the current degree bound:

$$
\ell+s\le M .
$$

This is absorb.

In other words, once the algorithm knows how to eliminate $\delta^{k_0}I_i$, it also knows how to eliminate all valid monomial multiples $\delta^{k_0+s}I_i$.

## 4. Ideal Method

The ideal method combines three ideas.

First, the search is incremental in $M$. It does not solve separate systems for $m=0,1,\ldots,M$. When the degree bound grows from $m$ to $m+1$, only the new coefficient unknowns

$$
u_{i,m+1},\qquad 1\le i\le N
$$

are considered.

Second, matrix columns are generated by a column oracle instead of repeatedly materializing full dense matrices. The column for $u_{i,k}$, corresponding to $E_{i,k}$, is the shifted series vector

$$
\operatorname{col}(i,k)_{(b,n)}
=
\begin{cases}
a_{i,b,n-k}, & n\ge k,\\
0, & n<k .
\end{cases}
$$

Third, absorb is part of the linear algebra. A coefficient unknown whose monomial-integral object is already covered by an accepted leading rule is never inserted as a new active column.

The algorithm maintains a column-echelon basis for the active columns. When a new non-absorbed unknown $u_{i,k}$ is processed, its column is reduced by the existing basis.

If the reduced column is nonzero, then this coefficient unknown is independent of previous columns and becomes a new basis column.

If the reduced column is zero, then the reduction coefficients give a new relation:

$$
E_{i,k}
+
\sum_{(j,\ell)<(i,k)}
r_{j,\ell}\,E_{j,\ell}
=0 .
$$

This relation is normalized, checked, accepted, and immediately used to absorb future coefficient unknowns.

## 5. Data Structures

### 5.1 Column Oracle

The column oracle returns the coefficient vector for $u_{i,k}$:

```text
column(i, k)[row(b, n)] = a[i][b][n-k] if n >= k
column(i, k)[row(b, n)] = 0             if n < k
```

It should be a shifted view of the input series, not a newly parsed or rebuilt matrix for every $m$.

### 5.2 Active Column Basis

The active basis stores independent columns in row-echelon form. Conceptually, each basis element contains:

```text
pivot_row
reduced_column
expression_in_original_variables
```

The `expression_in_original_variables` records how this basis column is represented by processed coefficient unknowns $u_{i,k}$. It is needed so that a dependent new column can be converted into an explicit polynomial relation among the corresponding $E_{i,k}$.

### 5.3 Accepted Relations

Each accepted relation stores:

```text
leading_integral_id
leading_delta_power
max_delta_power
terms
```

The terms represent

$$
E_{i,k}
+
\sum r_{j,\ell}E_{j,\ell}=0 .
$$

The leading coefficient is normalized to $1$.

### 5.4 Leading Rules

For each integral $I_i$, keep the accepted leading rules whose leading integral is $I_i$.

A rule with leading power $k_0$ and relation maximum power $q$ can absorb $u_{i,k}$ if

$$
k\ge k_0
$$

and

$$
q+(k-k_0)\le M .
$$

The shift is

$$
s=k-k_0 .
$$

## 6. Relation Normal Form

Whenever a new relation is obtained, it must be reduced by accepted relations before it is accepted.

Given a candidate relation $R$, repeatedly find the most complex object in $R$ that is covered by an accepted leading rule. Suppose this object is $E_{i,k}$ and the accepted rule has leading $E_{i,k_0}$. Let

$$
s=k-k_0 .
$$

Subtract the shifted accepted relation $\delta^s R_0$ from $R$ to cancel $E_{i,k}$.

Continue until no term is reducible.

If the normal form is zero, the candidate relation is only a consequence of already accepted relations and is discarded.

If the normal form is nonzero, normalize its leading coefficient to $1$ and check it.

## 7. Held-out Check

Every accepted relation must be checked on rows that were not used to generate it.

For a candidate relation

$$
R=
\sum_{(i,k)} r_{i,k}E_{i,k},
$$

the check condition is

$$
\sum_{(i,k)} r_{i,k}\,a_{i,b,n-k}=0
$$

for every held-out row $(b,n)$, with the convention that $a_{i,b,n-k}=0$ if $n<k$.

If this check fails, the relation is rejected. A rejected relation must not create an absorb rule.

## 8. Algorithm

Input:

```text
G
series data a[i][b][n]
maximum polynomial degree M
training row set R_train
held-out row set R_check
order of monomial-integral objects
```

Output:

```text
accepted normalized polynomial relations
leading absorb rules
```

Algorithm:

```text
initialize empty column_echelon_basis
initialize empty accepted_relations
initialize empty leading_rules

for each coefficient unknown u(i,k), ordered by E(i,k) from simpler to more complex up to degree M:
    if E(i,k) is absorbed by leading_rules:
        continue

    col = column_oracle(i,k) restricted to R_train
    expr = { E(i,k) : 1 }

    reduce col by column_echelon_basis:
        for each basis vector B whose pivot row appears in col:
            factor = col[B.pivot_row]
            col  -= factor * B.reduced_column
            expr -= factor * B.expression

    if col is nonzero:
        normalize col by its pivot entry
        normalize expr by the same pivot entry
        insert the new basis vector into column_echelon_basis
        continue

    candidate_relation = expr
    candidate_relation = normal_form(candidate_relation, accepted_relations)

    if candidate_relation is zero:
        continue

    normalize leading coefficient of candidate_relation to 1

    if candidate_relation fails held-out check:
        continue

    accept candidate_relation
    add its leading rule
```

The important point is that the algorithm processes coefficient unknowns once. It does not rebuild and solve a new matrix for every $m$.

## 9. Complexity

Let

$$
R=|R_{\mathrm{train}}|
$$

be the number of training rows.

Let

$$
C_{\mathrm{raw}}=N(M+1)
$$

be the raw number of monomial-integral objects, equivalently coefficient unknowns.

Let

$$
C_{\mathrm{eff}}
$$

be the number of coefficient unknowns that are not absorbed and actually enter the column basis reduction.

The current dense repeated approach has cost roughly

$$
\sum_{m=0}^{M} O(R\,C_m\,K_m),
$$

where $C_m=N(m+1)$ and $K_m$ is the rank at degree $m$.

The ideal incremental absorbing approach has cost roughly

$$
O(R\,C_{\mathrm{eff}}\,K_{\mathrm{eff}}),
$$

up to normal-form and check costs, where $K_{\mathrm{eff}}$ is the number of independent active basis columns.

The gain comes from three sources:

1. No repeated solve for $m=0,1,\ldots,M$.
2. No repeated construction of shifted dense matrices.
3. No insertion of columns whose monomial-integral objects are already absorbed by accepted relations.

This does not change the mathematical relation being searched. It changes the way the same formal-series linear constraints are explored.
