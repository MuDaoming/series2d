# 文档同步更新规则

## 核心原则

**修改代码后必须检查是否需要同步更新文档。**

## 触发条件与对应文档

| 操作 | 需要更新的文档 | 更新内容 |
|------|----------------|----------|
| 新增/删除源文件 | `docs/code_structure.md` | 文件组织部分（2.1节） |
| 修改类成员变量 | `docs/code_structure.md` | 对应类的描述（第4节） |
| 修改核心函数 | `docs/code_structure.md` | 对应类的核心函数和实现要点 |
| 修改约化公式 | `docs/problem_and_workflow.md` | 第3节约化公式 |
| 修改算法逻辑 | `docs/problem_and_workflow.md` | 第5节计算方法 |
| 完成待办项 | `docs/todo.md` | 勾选对应项，更新进度记录 |
| 新增待办项 | `docs/todo.md` | 添加新的待办事项 |

## 交流内容整理

与用户交流中产生的重要信息应整理进文档：
- **新设计决策** → 更新 `code_structure.md`
- **算法调整** → 更新 `problem_and_workflow.md`
- **新的待办事项** → 更新 `todo.md`

## 检查清单

每次修改代码后，请回答以下问题：
1. ☐ 是否新增/删除了文件？
2. ☐ 是否修改了类的成员变量或核心函数？
3. ☐ 是否修改了算法逻辑或约化公式？
4. ☐ 是否完成了某个待办项？

如果任一答案为"是"，请更新对应文档。
