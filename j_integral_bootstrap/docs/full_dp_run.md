# 完整 DP 全局运行记录

本轮目标是实际完成全部 147 个三 branch 活跃 sector 的 J 约化及 DE，
不是重复 44 维例子或 maximal cut 验证。对象、归一化及有限域定义沿用
[算法文档](problem_solution.md)。输入为 `j_integral_global/examples/dp_physical.json`，
固定 $p=1000003$、$d=26/7$，目标为 dot≤2 的 2952 个 J，另保留 230 个边界候选。
既定独立基底含 481 个 J 与 15 个边界函数，共 496 个主对象。

## 数据分工

所有目录位于 `j_integral_bootstrap/results/`。原生程序、family、目标与基底输入
会冻结到运行目录，指纹记录在 `identity.json`；每个点有完成回执及输出 SHA256。

| 目录 | 内容 | 用途 |
| --- | --- | --- |
| `dp_full/` | $t=17,\ldots,49$，33 个完整点 | 原始 pilot，含全部约化和 DE |
| `dp_cuts/` | 97 个廉价 cut 点 | 99 个 sector 的有理对角数据，1998 个非零系数 |
| `dp_exceptional/` | 33 个点，仅请求 90 条 DE 行 | 补齐不能由上述 cut 给出的对角输入，289 个非零系数 |
| `dp_extra_de/` | $t=50,\ldots,57$，331 条待处理 DE 行 | 只补未知耦合所需数据 |
| `dp_extra_reductions/` | $t=50,\ldots,57$，1763 个 J，跳过求导 | 补尚未完成的目标约化，并保留固定基底 |
| `dp_verification/` | $t=151,\ldots,158$，8 个完整点 | 独立最终验证，不能输入学习或拟合程序 |

完整点当前约需 2—3 分钟，90 行专用点约 33—42 秒，331 行专用点约 61 秒。
仅约化点的耗时另记在实际回执中；不能把所有这些不同任务按同一单点价格相加。
新鲜进程用 `/usr/bin/time` 分别记录用户 CPU、系统 CPU、峰值 RSS 和墙钟。
复用的旧点会明确标识来源，不能将其旧耗时算成本次新计算成本。

## 从头构造与包络学习

没有输入一份现成的完整 DP 有理 DE。对角数据由 cut 或专用数值行独立重建。
低层耦合构造完成后才能进入下一层；当前程序按数值依赖图的强连通块及其依赖闭包处理。

未知分母先由已知对角块、低层连接及已学习条目的极点构造候选。
逐因子删去不必要因子、提高单个因子的阶数，并用数值数据检验。
对候选分母 $D$，插值的是 $r(t)D(t)$ 的分子。每次学习至少保留 3 个内部检查点，
最终还必须通过上表中 8 个完全独立的全局点。

乘点值之前可预先缓存插值权重，以少量线性残差否决错误的分母假设；
没有必要为每个错误假设都构造完整分子多项式。
另保留不限制分子、分母次数对称性的 Euclidean 有理重构，避免漏掉低分子高分母情形。

解析性 Bootstrap 沿用原上游 PL-Hasse 内核；另用更充分的结构窗口和局部 jet 做过独立诊断。
普通端点规范因子、次数上界或极点阶数不足时，必须记录不相容并修正，不能强行接受结果。

## 大块拟合

已重建的系数作为有理函数恒等式固定，不作为新的未知量重拟合。
若分母和分子 cap 已确定，cap+1 个普通点足以将该条目固定为恒等式。

大块使用上游 `sampling_batch` 的原生联合消元思路，在原始极点参数中一起求解：

1. 全局次数约束；
2. 已知条目的有理恒等式；
3. 实际数值 IBP 数据。

按目标局部变量优先的列顺序消元，避免在每个取样点反复显式展开次数约束的核。
所有输出保留原始方程的有限域残差检查、参数坐标往返及独立 ansatz 求值检查。

## 运行入口与检查点

- `tests/collect_points.py`：完整点、指定导数行或跳过导数的本地取样。
- `native/reconstruct_partial.cpp`：保留所有已重建列，明确列出尚未重建项。
- `tests/bootstrap_global.py`：逐层全局 DE；可中断后从原子检查点恢复。
- `tests/bootstrap_reductions.py`：利用已经闭合的 DE 子空间逐 sector 约化目标。
- `tests/rational_learning.py`：共享极点见证与分子学习。
- `tests/native_fit.py`：原生联合稀疏拟合及残差证书。
- `native/verify_connection.cpp`：逐项验证完整连接，包括隐含零分量。

当前 DE 检查点为 `dp_complete_run/connection.json`，目标约化检查点为
`dp_reduction_run/reduction.json`。`status=running` 或 `need_points_or_envelope`
绝不代表完整计算已完成。最终结论以完整状态和独立验证报告为准。

本记录于 2026-11-06 运行期间维护；最终数目及耗时在完成后补入。


## 原包流程复核与失败尝试的控制

原包完整生产入口是 `production.run`。`upstream.pipeline.learn_anchor` 的输入包含一个参数赋值下完整的单变量有理 DE；这里的 anchor 不是单个 $t$ 数值点。它从这份结果学习分母因子对应、逐条目幂次及分子次数。`learn_profiles` 则测量构造模所需的有限求导阶数，不能代替分母学习。原包接口和实测见 `package_review.md` 及 `../official_route/README.md`。

本项目在首份完整有理 DE 尚不存在时，从已经成功重构的条目提供具体分母见证。整个块的分母最小公倍数可能过宽，应优先尝试同一方程行、同一主对象列的具体分母。还可先以候选 $D$ 乘数值系数 $r$，对 $rD=H/E$ 作 Euclidean 有理重构，最终得到 $r=H/(ED)$。这样允许自动恢复见证尚未包含的因子，而不必逐个猜测。所有这些尝试只使用学习点，最终独立验证点保留。

`tests/native_fit.py` 在大块联合求解前调用原包 `ProductionFitter` 的原生增量实现，只作单侧不相容筛查：前缀不相容便可否决该候选；相容或未定都不能省略后续已知有理恒等式和数值方程的联合求解。缺少原生库时不作此筛查，不允许静默进入昂贵的 Python 回退。实际失败 $6\times66$ 块在第 32 点出现矛盾，筛查约 0.63 秒；一个已经成功的三行 DP 块通过了不误拒回归。

`native/verify_reductions.cpp` 与 DE 验证器分别检查全部目标约化、全部主对象 DE，包括隐含零系数。目标约化验证器另有小型回归，覆盖主对象恒等式、零对象、错误零系数及缺失目标，避免只验证输出中显式非零项。


独立 sector 的调度不应被首个未解 sector 阻塞。两个 driver 已改为保留失败记录并继续处理依赖已经闭合的其它 sector；依赖尚未解出的 DE 块则明确等待，绝不使用未完成的下层 DE。完成标志仍要求所有 DE 行或所有目标通过，不能因为继续调度就将未解项默认为零。
