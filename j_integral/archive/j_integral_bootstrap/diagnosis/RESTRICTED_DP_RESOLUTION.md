# DP 六维块历史 AB 失败的直接原因

本诊断使用已完成的 `results/dp_final/connection_frozen.json` 作为真实有理函数输入，以及当时的 `dp_pole_route/merged_de49.json`、`refined_pending.json` 作为历史已知条目。未读取任何 fresh 验证点。真实 C 来源是物理六传播子子族的直接重构；本诊断不重新取得 IBP 样本。

## 最小反例

待处理块为六个 J，其中出错行是

$$T_6=J_{\{1,1,1,1,0,0,1,3\}}.$$

下层秩 47，C 有 239 个非零条目，当时已知 210 个、未知 29 个。历史最大包络是 block-column、power=2、growth=3：

$$D_{ij}=(q_{\rm source}q_{{\rm lower},j}\,t(t-1))^2.$$

用历史输入重建此包络，原始参数数 15787，原包 PL-Hasse 的约束后维数 1711，均与 `dp_complete_run/run_pending65.log` 的原运行逐字数值吻合。因此这里检验的是当时失败的包络，而不是事后缩减的替代问题。

在 $p=1000003$、$\tau=t-2/5$ 下，令

$$q=\tau+700002=t-\frac12.$$

下面三条真实系数含 $q^{-3}$，历史最大包络只允许 $q^{-2}$：

| 行 | 列 | 真分子/分母次数 | $q^{-3}$ 主部系数 mod p |
| --- | --- | --- | ---: |
| $T_6$ | $Bz0_{\{0,0,1,1,0,0,1,0\}}$ | 130 / 127 | 40452 |
| $T_6$ | $J_{\{0,0,1,1,0,0,0,1\}}$ | 98 / 97 | 58101 |
| $T_6$ | $J_{\{0,0,1,1,0,0,0,2\}}$ | 99 / 98 | 664725 |

三个系数均非零；因此无论多少数值点、多少 derivative source，都不可能让这三个函数落入原来的分母包络。原程序报不相容是正确行为。

九组原候选（row-diagonal/row-column/block-column，各 power=0,1,2）均没有包含完整真 C。最大两组也恰好还漏上述三个条目。真 C 的最高 growth 为 3，原 cap 已足够；这里不是分子次数不足，也不是漏掉一个新极点，而是已知 $t=1/2$ 极点的幂少了一阶。

## 排除另一处解析约束错误

只修改上述三条包络：分母各乘一个 $q$，cap 各加 1，以保持 growth=3。端点规范仍为 $(t(t-1))^3$，`extra_order=0` 不变。

- 原始参数数：15787 → 15790。
- 原包约束后参数数：1711 → 1712。
- 48 个因子的全部真实 C 主部，逐因子检查都属于相应的 `FactorBlock.basis` 行空间。
- 真实 C 同时满足全部分量分母与全局分子 cap。

成员检查完全是有限域多项式代数：对每个不可约因子 $q_a$，将 $N/D$ 的局部主部写成 $\sum_r p_r/q_a^r$；按原包的 `(row,column,pole,power)` 坐标组成一行，检查它是否属于该因子的基行空间。没有用有限个普通点代替有理函数恒等式。

原包旧空间仅在 $t=1/2$ 因子失败，另外 47 个因子均通过。修复包络后全部通过，说明这个例子的失败无需改变解析规范或 source-order 算法。三个遗漏主部受原包解析约束相关联，只新增一个独立方向。

## 复现

```bash
python j_integral_bootstrap/diagnosis/restricted_envelope.py
python j_integral_bootstrap/diagnosis/restricted_repair.py
```

输出位于 `results/dp_diagnosis/restricted/`：

- `old_envelope.json`：逐候选、逐条目的整除和 cap 检查，包含真分母和候选分母的因子幂。
- `repair_membership.json`：原空间与修复空间的逐因子精确成员检查。

这些结论固定在本例的运动学、d 和质数；不是对所有 setting 的幂次上界证明。

## 对下一次通用 J DE 的修复建议

候选分母幂是需要学习或验证的输入，不能把全局 `power<=2` 当作通用上界。当前程序提高 R、端点规范或分子 growth，都不能增加被禁止的 $q^{-3}$ 坐标。

较小的通用改进是：保存每个不可约因子的独立幂，并在所有当前候选不相容后，对已有极点逐个提高幂，配合原包解析约束及普通点检验；不要一开始把所有因子统一乘方。提高一个因子的幂时同步提高分子 cap，保持已有 growth 上界。已取得真实 anchor 时，优先用原包现有 denominator learning/transport 记录实际幂次；dot 增高后的条目不能沿用较低 dot 的固定幂上限。

本例的直接子族解还说明：高分子/分母次数不等于需要昂贵全局取样。先去掉从未出现的传播子、压缩物理输入，再复用同一个通用求解器，可以廉价取得学习 anchor。子族压缩和包络幂学习解决不同问题，均应保留。

## 不利用真实答案选择那三个位置，也能完成旧 65 点拟合

另做了一项更接近实际候选搜索的试验：给全部 29 个未知 C 分量的分母各乘一次同一个已知因子 $q=t-1/2$，cap 各加 1；不预先选择哪三个分量确实需要升幂，也不固定任何新增真实 C。

| 项目 | 原候选 | 全部未知条目提高此因子一阶 |
| --- | ---: | ---: |
| 原始参数数 | 15787 | 15816 |
| 原包约束后参数数 | 1711 | 1716 |
| 用于固定的旧有理条目 | 210 | 210 |
| 训练点 / 内部检查点 | 62 / 3 | 62 / 3 |
| 拟合结果 | 不相容 | 唯一，rank=1716 |

所用点为历史 $t=17,\ldots,81$，读取的是物理子族同一点的普通 IBP 数据；没有读取任何 fresh 验证点，也没有使用超出这 65 个 t 的点固定未知量。拟合后三个内部检查点全部通过，组装得到的整个 $6\times47$ 有理矩阵与直接重构真 C 逐项完全相等，包括 130/127 的最后一条。这个精确恒等式比较只用于确认结果，没有参与拟合。

因此，本例当时的 65 点本来足够。失败不是需要大量补点才能固定剩余系数，而是旧候选缺少了正确的极点阶。这个试验支持对已有因子逐个升幂的候选策略：本次仅增加 29 个原始参数，AB 后只增加 5 个自由参数，就完成了旧点上的唯一拟合。

这里 `extra_order` 始终为 0；分母幂 k 提高时，原包默认的局部 source-order 计划也会按新 k 生成。这是原算法对修正包络的正常响应，不是手工增加独立的导数余量，更没有修改端点规范。
